## 6. Environment & Security Audit

- `.env.local` is untracked (gitignored) and contains **publishable/anon keys only** — `VITE_CLERK_PUBLISHABLE_KEY`, `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`. Values were never echoed in any report or output.
- Source scan for secret-shaped strings (`service_role`, `sk_svc_`, `sb_secret_`, JWT fragments) across `src/**` found only **documentation text** in `src/services/shared.ts` and `src/services/index.ts` (comments explaining the anon-only policy) — no hardcoded keys or tokens in code.
- `src/lib/supabase.ts` prefers `VITE_SUPABASE_PUBLISHABLE_KEY`, falling back to `VITE_SUPABASE_ANON_KEY`; `src/lib/clerk.ts` reads `VITE_CLERK_PUBLISHABLE_KEY`.
- **Added `.env.example`** listing all four variable names (including the optional `VITE_SUPABASE_ANON_KEY` alias) with no values. `src/vite-env.d.ts` references `vite/client` types; env vars are accessed via `import.meta.env` with string casts.

## 9. Remaining Legacy Concerns

- **Git:** `git` is not installed on this machine and the project tree is **not a Git repository**. §5/§6 hygiene (`.gitignore`, `.env.example`, untracked artifacts) is ready for the moment a repo is initialized; no commit history exists to rewrite.
- **`opendesign/` + `Python/`:** intentionally kept but excluded from version control. If the design-preview workflow is retired later, both can be deleted wholesale.
- **Live authenticated flows** (Clerk sign-in / Supabase RLS round-trips) remain unverified in this environment — they need a second machine with valid Clerk/Supabase credentials (see Phase 7 report §7).
- **Chunk-size warning:** single 683 kB JS chunk is above Vite's 500 kB advisory threshold. Bundling-cleanup (lazy routes, manualChunks) is a future performance task, not a correctness issue.
